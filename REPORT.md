## 2. Мета роботи

Завершити Java-продукт: замінити прямий список параметризованим сховищем, додати власний
виняток із ланцюгом причин, описати CSV-стовпці анотацією, реалізувати універсальний
рефлексивний експортер, записати файл через `Path`/`Files` з UTF-8, прочитати його назад і
довести рівність об'єктів.

Досягнуто:

- `Repository<T>` і `DataStorageException`;
- `@CsvColumn`, універсальні `CsvExporter<T>`, `CsvParser`, `CsvImporter<T>`. Вони лежать в окремому
  пакеті `ua.lpnu.kzp.storage` і не містять жодної назви предметного класу;
- `MedicineRecord` і параметр `--export` з автоматичною перевіркою round-trip;
- завдання із зірочкою: `Exporter<T>` + `JsonExporter<T>` і кеш полів;
- стандартний звіт не змінився; 154 тести (було 101).

## 4. Repository<T>

```java
public final class Repository<T> {
    public void add(T item)
    public void addAll(Collection<? extends T> newItems)
    public List<T> all()                                   // незмінний знімок
    public List<T> find(Predicate<? super T> condition)    // незмінний список
    public Optional<T> findFirst(Predicate<? super T> condition)
    public int size()
}
```

- **Параметр типу** `T` фіксується під час створення (`new Repository<Medicine>()`). Компілятор не
  дасть додати рядок у сховище препаратів, і методи повертають `Medicine` без приведення типів.
  Raw types не використовуються.
- **Знімок**: `all()` повертає `List.copyOf(items)`. Ззовні неможливо змінити внутрішній список,
  а подальші `add` не змінюють уже виданий знімок (тест `allReturnsIndependentUnmodifiableSnapshot`).
- **Предикат** `Predicate<? super T>` дозволяє передати умову для надтипу, наприклад
  `Predicate<Number>` для `Repository<Integer>` (тест `findAcceptsPredicateOfSupertype`).
- `addAll(Collection<? extends T>)` приймає, наприклад, `List<FreeMedicine>` для `Repository<Medicine>`.
- `null` відхиляється (`NullPointerException`).

## 5. Модель даних

```java
public record MedicineRecord(
        @CsvColumn("назва") String name,
        @CsvColumn("форма") String form,
        @CsvColumn("ціна") double price,
        @CsvColumn("придатність") LocalDate expiresOn,
        @CsvColumn("рецепт") MedicineKind prescription)
```

(Назви стовпців винесено в константи `MedicineRecord.NAME` тощо, щоб фабрика `fromCsv` і
анотації використовували ті самі рядки.)

- **Інваріанти** (компактний конструктор): жоден об'єктний компонент не `null`; назва й форма
  непорожні; ціна скінченна та ≥ 0.
- **Чому `LocalDate`, а не `daysToExpire`**: кількість днів залежить від дня звіту. Файл,
  прочитаний завтра, з тими самими числами означав би інші дати. `from(medicine, today)`
  обчислює `today + daysToExpire`, а `toMedicine(today)` — навпаки (і відхиляє прострочені записи).
- **Чому `MedicineKind`, а не `boolean`**: категорія — фіксована множина значень, тобто enum
  (вимога методички); у CSV пишеться ім'я константи `PRESCRIPTION`/`FREE`.
- **equals/hashCode**: record порівнює всі п'ять компонентів. Саме таке порівняння потрібне для
  round-trip, щоб перевірити, що відновилося все, а не лише ключ. Ключ запису для звіту
  (`key()` = назва + форма) збігається з логічною рівністю `Medicine` з ЛР3.

## 6. @CsvColumn

```java
@Documented
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
public @interface CsvColumn { String value(); }
```

- `RUNTIME` — анотація лишається в байт-коді й доступна рефлексії під час роботи програми.
  З `CLASS` чи `SOURCE` `getAnnotation` повернув би `null`.
- `FIELD` — лише поля. На компонентах record компілятор переносить її на приватне поле.
- **Назви стовпців** беруться лише з `value()`.
- **Порядок стовпців** — алфавітне сортування Java-імен полів, бо `getDeclaredFields()` порядку не
  гарантує: `expiresOn`, `form`, `name`, `prescription`, `price` → «придатність, форма, назва, рецепт, ціна».

## 7. Рефлексивний експортер

`AnnotatedFields` (пакет `storage`, кешується через `ClassValue`):

1. `type.getDeclaredFields()` повертає всі поля класу, включно з приватними (на відміну від
   `getFields()`, що дає лише публічні разом з успадкованими);
2. `filter(isAnnotationPresent(CsvColumn.class))`, без статичних полів;
3. `sorted(comparing(Field::getName))`;
4. `trySetAccessible()` для кожного поля. Якщо доступ не відкрито (клас з іншого модуля),
   поле запам'ятовується, і `of()` кидає `DataStorageException`, а не мовчки пропускає стовпець;
5. значення читає `field.get(record)`, а `IllegalAccessException` загортається в `DataStorageException`.

`CsvExporter<T>`:

- **заголовок** — `@CsvColumn.value()` полів через кому, з екрануванням;
- **рядки** — `String.valueOf(value)`: для `double` формат не залежить від локалі (`45.5`), для
  `LocalDate` — ISO (`2027-11-25`), для enum — ім'я константи. `null` записується як порожнє поле;
- **екранування** (RFC 4180): значення з `,` `"` `\n` `\r` береться в лапки, внутрішні лапки
  подвоюються;
- у коді немає `instanceof`, назв класів чи умов за підтипом. Тест `ExportersTest` експортує
  звичайний клас `Book` (з неанотованим і статичним полями) і record `Point`.

**Чому потрібен `Class<T>`**: для порожнього списку немає жодного об'єкта, з якого можна було
б дізнатися клас. Без `Class<T>` не вийде навіть заголовка. До того ж generics стираються під
час компіляції, тож `T` під час роботи програми невідомий.

## 8. Формат CSV

- кодування UTF-8 (явно при записі й читанні), роздільник полів — кома;
- роздільник записів — `System.lineSeparator()` (CRLF у Windows, LF в Unix), а парсер приймає обидва;
- перший рядок — заголовок `придатність,форма,назва,рецепт,ціна`.

Приклад (`data/medicines-sample.csv`, 6 записів, 8 фізичних рядків):

```text
придатність,форма,назва,рецепт,ціна
2027-11-25,таблетки,Парацетамол,FREE,45.5
2027-05-24,капсули,Амоксицилін,PRESCRIPTION,128.9
2026-12-09,мазь,"Мазь ""Левомеколь"", 40 г",FREE,89.75
2026-12-15,розчин,"Інсулін
швидкої дії",PRESCRIPTION,640.0
2026-12-25,таблетки,Цетиризин,FREE,52.3
2028-11-24,краплі,Вітамін D3,FREE,210.0
```

Рядок 4 містить кому й лапки, рядок 5–6 — перенесення рядка всередині значення.

Експорт `data/pharmacy-full.csv` (`--export out/medicines.csv --date 2026-11-25`) дає 14 рядків:
заголовок і 13 записів.

## 9. Імпорт і round-trip

**Алгоритм відновлення** (`CsvImporter.read`):

1. `Files.readString(path, UTF_8)` → `IOException` загортається в `DataStorageException`;
2. `CsvParser.parse(text)` — посимвольний автомат зі станом «у лапках / поза лапками». Він не
   плутає кому й перенесення рядка в лапках з межами поля чи запису, приймає CRLF і LF,
   пропускає BOM і порожні рядки, для кожного запису запам'ятовує номер фізичного рядка;
3. перший запис має збігатися з очікуваним заголовком, який береться з анотацій класу;
4. для кожного наступного запису перевіряється кількість полів і будується карта «стовпець →
   текст», а з неї предметна фабрика `MedicineRecord::fromCsv` створює об'єкт;
5. перша ж помилка зупиняє імпорт. Відновлення з файла має дати або всі записи, або жодного.

**Чому не `split(",")`**: рядок `"Мазь, 40 г",1` має два поля, а `split` дасть три. Перенесення
рядка в лапках розбило б запис на два ще під час читання файла по рядках (тест
`commaInsideQuotesBelongsToValue`).

**Порівняння**: `restored.equals(records)` — `List.equals` порівнює поелементно через
`MedicineRecord.equals`, тобто всі п'ять компонентів і порядок.

Доказ round-trip:

- `MedicineRecordTest.roundTripRestoresEqualRecords`: 5 записів, серед них з комою й лапками,
  з перенесенням рядка, з пробілами на краях і з ціною 0. Записані й прочитані списки рівні;
- `roundTripOfModelMedicines`: `Medicine` → `MedicineRecord` → CSV → `MedicineRecord` →
  `Medicine`. Збігаються підтип, ціна й `daysToExpire`;
- `MedicineArchive.export` (CLI `--export`) після запису читає файл і порівнює. У CI на трьох ОС:
  «Експортовано 13 записів у CSV … round-trip: відновлено 13, усі рівні початковим».

## 10. Помилки

| Рівень | Ситуація | Повідомлення | `getCause()` | Тест |
|--------|----------|--------------|--------------|------|
| файл | файл не існує | `не вдалося прочитати файл …` | `NoSuchFileException` (`IOException`) | `missingFileKeepsIoCause` |
| файл | запис у каталог замість файла | `не вдалося записати файл …` | `IOException` | `writeErrorKeepsIoCause`, `fileErrorIsReportedWithCause` |
| синтаксис CSV | незакриті лапки | `рядок N: незакриті лапки` | — | `unclosedQuoteIsError` |
| синтаксис CSV | символ після закривальних лапок / лапки в середині поля | `рядок N: …` | — | `characterAfterClosingQuoteIsError`, `quoteInsideUnquotedFieldIsError` |
| структура | порожній файл без заголовка | `файл порожній: немає рядка заголовка` | — | `completelyEmptyFileIsError` |
| структура | чужий заголовок | `очікується заголовок […], отримано […]` | — | `wrongHeaderIsRejected` |
| структура | хибна кількість полів | `рядок 2: очікується 5 полів, отримано 4` | — | `wrongFieldCountReportsLine` |
| формат значення | ціна не число | `рядок 2: ціна має бути числом, отримано "дорого"` | `IllegalArgumentException` → `NumberFormatException` | `badNumberKeepsNumberFormatCause` |
| формат значення | хибний enum | `рядок 3: рецепт має бути PRESCRIPTION або FREE, отримано "ЗА_РЕЦЕПТОМ"` | `IllegalArgumentException` → `IllegalArgumentException` (`valueOf`) | `badEnumKeepsCause` |
| формат значення | дата не ISO | `рядок 2: дата придатності має формат РРРР-ММ-ДД …` | `IllegalArgumentException` → `DateTimeParseException` | `badDateKeepsDateTimeParseCause` |
| модель | порожня назва, від'ємна ціна, `NaN`, `null` | `IllegalArgumentException` / `NullPointerException` | — | `constructorValidatesState` |
| рефлексія | клас без `@CsvColumn` | `клас … не має полів з @CsvColumn` | — | `classWithoutAnnotationsIsRejected` |
| рефлексія | поле недоступне | `не вдалося прочитати поле …` / `немає доступу до полів …` | `IllegalAccessException` | (шлях захищено `trySetAccessible`) |
| CLI | хибна `--date` | `хибна дата «2026-13-01», очікується РРРР-ММ-ДД` | `DateTimeParseException` | `invalidDateIsUsageError` |

`DataStorageException` — checked-виняток. Компілятор змушує `Main` обробити його: програма
виводить повідомлення й рядок `Причина: …` і завершується з кодом 1. Порожніх `catch` у коді
немає.

## 16. Відповіді на контрольні питання

1. **Навіщо параметр типу в Repository<T>.** Один клас сховища працює з будь-яким типом, але
   кожен екземпляр типобезпечний: компілятор не дасть додати чужий об'єкт, а результат не
   потребує приведення типів.
2. **Параметризований клас і raw type.** `Repository<Medicine>` перевіряється компілятором.
   Raw `Repository` вимикає перевірки типів, `get` повертає `Object`, і помилка з'являється
   лише під час роботи як `ClassCastException`.
3. **Навіщо Predicate<? super T>.** Щоб приймати умову, написану для надтипу (наприклад,
   `Predicate<Object>` чи `Predicate<Medicine>` для сховища підтипу). Такий предикат уміє
   перевірити будь-який `T`.
4. **Чому all() повертає незмінний знімок.** Інакше зовнішній код міг би змінити внутрішній
   стан сховища в обхід `add` і його перевірок, а ітерування ламалося б від одночасних змін.
5. **Checked exception.** Виняток, який компілятор змушує або обробити, або оголосити в
   `throws`. Він доречний для очікуваних зовнішніх збоїв: файл недоступний, дані пошкоджені.
   Викликач мусить свідомо вирішити, що з цим робити.
6. **Навіщо cause.** Щоб не втратити первинну технічну деталь (`NoSuchFileException`,
   `NumberFormatException`) і її стек. Наше повідомлення пояснює, що сталося на рівні
   програми, а причина пояснює, чому.
7. **Path і Files проти рядків.** `Path` сам підставляє роздільник ОС, нормалізує й порівнює
   шляхи. `Files` дає атомарні операції з явним кодуванням і зрозумілими винятками.
8. **Кодування і при записі, і при читанні.** Байти у файлі не несуть інформації про
   кодування. Якщо одна сторона використає типове кодування ОС (наприклад, cp1251), кирилиця
   зіпсується.
9. **@Retention(RUNTIME) і @Target(FIELD).** Перша зберігає анотацію в класі й робить її
   видимою рефлексії під час виконання. Друга дозволяє ставити анотацію лише на поля.
10. **Чому анотація не виконує експорт сама.** Анотація — лише метадані без поведінки. Діє
    код, який її читає (наш `CsvExporter`).
11. **getDeclaredFields() і getFields().** `getDeclaredFields()` повертає всі поля самого
    класу, включно з приватними, але без успадкованих. `getFields()` повертає лише публічні
    поля, зокрема успадковані.
12. **Навіщо перевіряти trySetAccessible().** Модульна система може заборонити доступ до
    приватних полів. `trySetAccessible()` повідомляє про це `false`, і можна видати зрозумілу
    помилку замість `InaccessibleObjectException` чи мовчки пропущеного стовпця.
13. **Чому порядок полів детермінований.** `getDeclaredFields()` порядку не гарантує. Без
    сортування стовпці могли б переставлятися між запусками чи JVM, і файл не читався б назад.
14. **Чому не split(",").** Кома й перенесення рядка можуть бути всередині значення в лапках,
    а лапки ще й подвоюються. `split` нічого цього не враховує.
15. **Екранування.** Значення з комою, лапкою або перенесенням рядка береться в подвійні
    лапки, а кожна лапка всередині подвоюється: `Мазь "Левомеколь", 40 г` →
    `"Мазь ""Левомеколь"", 40 г"`.
16. **Навіщо Class<T> для порожнього списку.** Через стирання типів `T` під час виконання
    невідомий, а в порожньому списку немає об'єкта, з якого взяти клас. Без `Class<T>` не
    побудувати навіть заголовок.
17. **Універсальний експортер і fromCsv.** Експортер знає лише механіку: поля з анотацією,
    екранування, файл. `fromCsv` знає предметні правила: типи полів, формат дати, допустимі
    значення enum, інваріанти.
18. **Рівні помилок.** Файлові (`IOException`), синтаксичні (лапки), структурні (заголовок,
    кількість полів), формат значення (число, дата, enum), валідація моделі (інваріанти),
    рефлексія (немає анотацій, немає доступу), аргументи CLI.
19. **Що доводить round-trip.** Що експорт і імпорт узгоджені: для будь-яких допустимих даних,
    зокрема з комами, лапками й перенесеннями, файл однозначно відновлюється в рівні об'єкти,
    і нічого не губиться й не спотворюється.
20. **Чому не порожній catch.** Він приховує збій: програма продовжує роботу з неповними чи
    хибними даними, а причину вже не знайти. Помилку треба обробити, передати далі або
    загорнути з `cause`.

## 17. Висновки

Java-продукт «Аптека» завершено: дані зберігаються в типобезпечному `Repository<T>`, а
експорт і імпорт виконує універсальна рефлексивна інфраструктура на основі `@CsvColumn`.
Помилки мають власний checked-виняток із причинами. Round-trip доведено тестами й
автоматичною перевіркою в CLI на трьох ОС.

Файл `--export` (UTF-8, заголовок, RFC 4180, ISO-дати) — стандартний CSV. Наступний програмний
блок (Python, ЛР6–ЛР7) може читати його `csv.DictReader` з `encoding="utf-8"` без жодного
знання про Java: назви стовпців беруться із заголовка, перенесення рядка в лапках модуль
`csv` обробляє сам.
